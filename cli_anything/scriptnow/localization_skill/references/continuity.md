# 连续性与中断恢复

## 一个当前依据

沿用已有项目材料；本地长篇可用一个索引指向当前来源范围、目标约定、人物与文化决策、章节状态。文件名不固定，不强制数据库或多份表格。平台模式以已采纳版本为准，本地缓存记录其 ID/版本，不另立事实源。候选中的新设定保持“待确认”，不能悄悄覆盖已确认约定。

除名字外，按故事实际需要追踪：身份与称谓/别名、人物关系及其变化、机构权力与限制、资源相对价值、距离与行动时间、时间地点、角色已知与未知信息、伏笔与承诺、叙述视角和声音、人物在不同关系中的俚语/称呼/语域、保护项及待核实假设。来源断言附原文定位；推测明确标注，不猜首次出场章号。记录每次改动影响哪些后续章节。

## 每章由 Agent 执行

开写前实际读取当前约定、本章原文、前章结尾及相关人物/伏笔；说明本章需要承接的状态。只加载相关内容，不把全书塞进每次上下文。完成后回读实际文件，核对别名、职位、时间、关系、知识边界及事件后果；按真实内容更新状态，记录本章改变了什么、留下什么。术语检索只验证拼写，不能证明社会关系和因果成立。

新人物/新制度先查已有决策；冲突不能靠偷偷改名或泛化为另一种制度解决。局部纠错后检查所有受影响位置，更新主记录，保留变更原因；不要仅改 Localization notes。

## 中断后恢复

恢复记录只需足以继续：当前工作范围、已读范围和缺口、当前版本/决策、已完成稿件、未解决问题、下一步。新会话先读索引和相关原文，再写下一单元，不凭聊天记忆声称记得所有设定。记录缺失时检查现有稿件重建可证实部分，未知项留下，不假造历史。

涉及上游方案变更，保留旧稿并标明受影响内容需复核，不批量覆盖作者确认稿。平台需遵守版本依赖和前序工作包采纳门禁；本地也按章节因果串行推进，不用并行写章来绕过连续性。
