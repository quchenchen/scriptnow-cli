# 翻译工作流

本文件描述网文归化翻译的完整流程与节点。全书翻译走完整七阶段；局部试译/单章审校可从对应阶段介入，不强制从头走。每个阶段的产出是下一阶段的前提——上游未完成，下游不开工。

---

## 阶段总览

```
0. 启动确认
   ↓
1. 通读与原著分析
   ↓
2. 世界观设定（全局决策）
   ↓
3. 角色设定（全局决策）
   ↓
4. 大纲与结构规划
   ↓
5. 试译验证（选风险最高的场景）
   ↓    ← 作者确认后才继续
6. 逐章翻译（串行推进）
   ↓
7. 审校与交付
```

---

## 0. 启动确认

**做什么**：在动笔前，明确本轮任务的边界。

需要确认的信息：
- **原文范围**：全书 / 指定章节 / 单章试译？原文是否完整可读？
- **目标语言与地区**：英文美区/ 英文英区 / 其他？（目标语言不自动决定故事背景所在地）
- **本地化深度**：全本土化（命名/制度全部西化）/ 保留中国背景但用英文连载/ 局部改写？
- **姓氏策略**：默认全英文姓；若保留华裔身份角色，由作者明示并挂"华裔"标签；无授权保留时交付前需清理 Mrs. Chen / Tessa Liu 这类"英文名+中文姓拼音"残留。
- **品类确认**：现言霸总/ 狼人 / 黑帮 / 校园 / 奇幻 / 其他？品类决定调用哪套术语和命名语法。
- **叙事视角（POV）**：默认全书单一第一人称；承载角色按题材建议（现言/狼人/虐恋默认女主 I-POV；黑帮看权力线；男频升级默认男主 I-POV）。双 POV 需作者明示；一旦开启，按整章为单位切换，不在一章内跳 POV。
- **交付节奏**：默认逐章创作 + 每 5 章合并审查稿（`ch001-005.md`…）。合并稿只拼接不润色，开头附一段"本批交付说明"（覆盖区间、每章钩子类型、关键决策变更、待确认事项）。
- **作者保护项**：哪些事件、关系、效果或具体载体不能改？按作者原话记录，不自行解释。
- **参考资源**：作者是否提供术语表、翻译规范（如《网文本地化规范》）、已有稿件？作者文件优先于本 skill 的通用规则。

**完成标准**：以上信息已明确，或缺失项已标为待确认并告知作者。

**作者介入点**：本地化深度、POV、交付节奏、作者保护项必须由作者决定或采用默认后记录，不自行假设。

## 1. 通读与原著分析

**做什么**：读清原文，建立叙事骨架。不能把「抽取成功」或「读了开头」当通读。

分段读取（长篇按章节/段落 offset读），记录：
- **故事驱动**：核心冲突是什么？谁有什么欲望，遭遇什么阻力，做出什么选择，产生什么后果？
- **叙事结构**：有哪些主要情节线？关键转折点在哪？
- **文化机关**：有哪些靠中式制度/称谓/发音/字形驱动的悬念、笑点或伏笔？（这类直译必定失效，需在阶段2/3决策）
- **品类卖点**：哪些场景/设定是目标读者期待的核心体验？（这些优先保护）
- **待核实项**：有哪些制度、职位、法律关系或数字尚不确定能否直接迁移？

**产出**：原著分析摘要（连贯叙述，不是填表）。长篇可分批产出，按卷/章节区间为单位。

**完成标准**：已实际读完本轮需处理的所有章节；截断或漏读的部分已明确标注，不以推断充数。

**注意**：无原文时只能交付标注「合成示范」的改写样例，不得冒称指定章节已分析完毕。

## 2. 世界观设定（全局决策）

**做什么**：确定目标世界的背景框架，记录影响全书叙事的制度性决策。不填百科全表，只展开当前情节和已知主舞台需要的部分。

需要决策的层面（只有影响剧情时才深挖）：

**背景框架**
- 真实世界 / 虚构世界 / 架空背景？
- 时代与生活条件（现代都市 / 近未来 / 历史背景）？
- 什么组织控制稀缺资源（钱、权力、血脉、魔法）？
- 违反规则的代价是什么？

**制度与权力**
- 核心机构（公司/家族/Pack/黑帮/政府）的权力边界是什么？谁能命令谁？
- 中式制度（派出所/单位/户籍/彩礼等）如何迁移？先查英文规范中的判断标准。
- 法律与数字是否符合目标地区现实（刑期/赔偿/合同）？数字必须能自洽。

**地理与时间**
- 地名如何处理（全部虚构化/ 保留真实城市 / 混合）？
- 节日/时间轴如何对应目标文化？

**货币与资源**
- 人民币→美元，豪门数字量级如何定（读者爽感vs. 现实合理性）？
- 金额在剧情中的「重量」是否维持（随手花掉 / 需要积攒 / 足以翻身）？

**文化机关处理**
- 对阶段1中标记的文化机关，逐一过「机关重建三问」：
  1. 原机关承担什么功能（悬念/笑点/伏笔/隐瞒）？
  2. 英语里用什么手段实现同一功能？
  3. 新机关能否全书自洽运行？
- 三问都通过才落决策；不能硬译，也不能删掉。

**产出**：世界观决策记录（原文位置 → 原功能 → 目标处理 → 理由/依据 → 状态：已确认/待核实）。只记录真正做了决策的元素，不填空项。

**完成标准**：影响开篇和主要情节的制度性设定已决策，待核实项已标明，作者保护项已检查不冲突。

**作者介入点**：触碰作者保护项时，提交冲突描述并等待作者裁决，不自行决定。

## 3. 角色设定（全局决策）

**做什么**：为全书角色建立命名、称谓和声线档案，确保全书一致。

**命名决策**
- 按角色地位分配名字风格（见英文输出规范 §二）。
- 检查：首字母冲突（同书同首字母角色 ≤2个）、音节/尾音防脸盲、IP强绑定禁用名。
- 目标语言为英文时，按品类调用对应命名语法（狼人/黑帮/校园各有专属命名池）。
- 有隐藏身份的角色：提前规划两套名字及切换时机。

**称谓决策**
- 中式职场称谓（陆总/贺律师/大少爷）如何处理（见英文输出规范 §三）？
- 亲属称谓的关系距离如何在目标语言中保留？
- 同一角色在不同关系/场合的称谓切换规则是什么？

**声线档案**
- 每个主要角色的语域特征：年龄、职业、阶层、性格在语言上的体现。
- 粗口密度按角色人设定，不按品类统一配给。
- 配偶/亲密关系的私下称呼 vs. 正式场合称呼如何切换。

**产出**：角色档案（人名对照表 + 称谓规则 + 声线关键词）。格式不固定，以能查阅为准。

**完成标准**：主要角色命名已定，不存在首字母堆积或脸盲风险；声线差异化策略有据可查。

**注意**：萌娃绰号优先，正式场合才用本名；配偶私下直呼其名，正文不反复出现 husband/wife。

## 4. 大纲与结构规划

**做什么**：在全文层面规划章节处理顺序、标题本地化和结构调整。

**章节标题本地化**
- 以原标题核心意思为基础，不逐字翻译。
- 原则：只点事件/情绪/钩子，不点答案（去剧透化）。
- 避免：直接截取人物对话做标题（生硬直译）；一眼穿透剧情走向（剧透）。

**节奏与钩子规划**
- 确认哪些章节是关键情节节点（转折/高潮/揭秘）。
- 确认品类特有的钩子放置规则（如狼人文：fated mate/rejected mate是中后期钩子，前5章不用掉）。
- 检查原文节奏：章节划分在目标市场是否合适？是否需要合并/拆分？
- **每章钩子预规划**：在工作批次计划里按章预先标注章末钩子的目标类型（信息揭露/行动悬停/关系转折/威胁升级/身份暴露/时间压迫），同一类型不得连续两章重复；禁止总结式/预告式/情绪抒发式收尾（见英文输出规范 §八）。

**工作包规划**
- 以 **5 章为默认交付单位**划分工作批次；每批对应一个合并审查稿 `ch00N-00N.md`。
- 若原文的情节单元跨越 5 章边界（例：某情节高潮落在第 7 章），记在批次备注里，提示作者"下一批 ch006-010 会包含该高潮"，但**不打破 5 章节拍**——让钩子密度保持稳定。
- 记录每个批次的起止章节、依赖的前置决策、预计触碰的敏感点。

**产出**：章节标题对照表（原标题 → 本地化标题 → 备注）+ 工作批次计划。

**完成标准**：标题对照表已覆盖全书（或本轮范围），工作批次划分已定。

---

## 5. 试译验证

**做什么**：在全面展开前，选最容易失效的场景试写，验证世界观/角色决策是否真能在正文中成立。

**选场景的标准**（按风险从高到低）：
1.有文化机关的场景（悬念/笑点依赖中式机制）
2. 核心关系场景（主角间第一次真正冲突/亲密）
3. 制度权力发挥关键作用的场景（靠体制压制人物的关键戏）
4. 品类高光场景（狼人变身/黑帮谈判/霸总施压）

**试写要求**：
- 说明要验证的具体疑问（不是泛泛地「看看效果」）。
- 试稿显示：人物为何行动、新载体如何施加压力、原有体验是否仍能产生。
- 检查：语言声音是否对、POV是否保持、信息释放时机是否正确。

**验证结论**：
- 失败：定位问题，回修阶段2或3的决策，再试。
- 成功：只证明该样段问题解决，不代表全书验证通过。

**作者介入点**：试稿完成后展示给作者，明确确认后才进入阶段6。作者确认记录在项目索引里。

**完成标准**：至少一个高风险样段通过验证，作者已确认方向。

> **注意**：单场景试译验证的是"这类高风险场景能不能成立"；完整节奏能不能站住是**首批 5 章 gate** 的事（见 [批次生产协议](batch-production.md) §二）。两者都要做，顺序是：单场景试译确认 → 首批 5 章 ch001-005 当试写 → 作者确认 → 从第二批 ch006 起批量。

## 6. 逐章翻译

**做什么**：在已确认的世界观/角色/试译方向上，串行推进正文翻译。每章独立执行以下循环；每完成 5 章出一个合并审查稿。

**批次节奏**：批次启动前读三层资料（全书基础 / 当前卷 / 近期衔接）、首批 5 章作为 gate、每卷结束后插卷级审核、正文生成与文学审核两遍分离 —— 这些批次与卷级的协议统一在 [批次生产协议](batch-production.md)，本节只管每章循环。

### 每章执行循环

**开写前**（不可省略）：
1. 读取当前项目索引，确认本章涉及的角色、关系、伏笔和上章状态，确认本章 **POV 承载角色**与项目索引登记一致。
2. 实际读取本章原文（不依赖记忆或摘要）。
3. 读取上一章结尾，确认需要承接的情绪和信息状态；确认本章章末钩子的目标类型，与上一章不重复。
4. 说明本章要解决的核心叙事问题（谁做了什么，推动了什么），并明确本章钩子落点在哪一段。

**写作中**：
- POV：全章锁定承载角色 first-person（或项目索引登记的其他模式），不中途跳人称、不跨段跳到另一个人内心；双 POV 模式下也以整章为单位，开章前须明示切换。
- 对白：短、狠、有来有回，英文每句不超过 15 词；换说话人换段落；对话标签以 said/asked 为主，避开"smiled and said / laughed coldly / said with a cold snort"等黑名单。
- 对话不是水剧情：每轮对白必须推动信息差、权力博弈或关系温度之一；客套/点头/"是好的"等水对白压缩或替换为动作。
- 叙述：靠动作和短句制造情绪，不堆形容词（避免三个以上并列形容词修饰同名词）；内心独白用星号括起（\*...\*）；社媒消息用方括号（[...]）。
- 文化元素：遇到未在阶段2/3决策过的新元素，先暂停标注，补决策后再写，不自行发明解决方案。
- 新人物：先查角色档案；档案中没有的，按命名原则选名并立即更新档案；中式姓氏默认改英文姓（Chen→Carter 等），作者授权保留华裔身份时才用拼音姓。
- 章末钩子：按预规划类型，最后 1–2 句承担钩子；钩子句不解释、不总结、不抒情。

**写完后**（不可省略）：

**① 每章自查清单**（10 项，不通过就回修，不交付单章文件）：
1. **POV 一致性**：全章锁定在项目索引登记的承载角色上？没有中途跳人称或跳到另一个角色的内心？
2. **拼音残留**：搜稿件有没有汉语拼音姓名（Chen/Liu/Wang/Zhang+名）、中文地名音译（Ning City/Beijing 类未授权保留）、中式称呼（Young Master / Director Lu）？
3. **公制残留**：搜 km / kg / cm / ℃ / 公里 / 公斤 / 米 / 摄氏度 / 元 / 人民币？
4. **中式日常载体**：筷子/油条/豆浆/民政局/拜堂/红包/微信/微博/抖音 —— 按本书本地化深度统一处理，不能这章换那章没换。
5. **对话节奏**：有没有超过 15 词的英文对话？有没有"客套来回/点头/是好的"的水对白？
6. **对话标签**：有没有 smiled and said / looked at her and said / laughed coldly 之类黑名单？said 占比够不够？
7. **叙述风格**：有没有堆砌形容词？情绪有没有靠动作短句承担？
8. **第三人称自指**：角色指代自己时有没有误用 your uncle / your husband 等（非俏皮语境）？
9. **章末钩子**：最后 1–2 句是不是钩子句？不是总结、不是预告、不是情绪抒发？和上一章钩子类型是否不同？
10. **术语一致性**：本章新出现的专名（人名/地名/公司名/道具名）是否已登记到术语表？已登记过的是否沿用唯一译法？

**② 回读与更新**：
1. 回读实际稿件，核对：人名别名、职位、时间轴、关系、角色知识边界。
2. 检查本章是否新增了需要记录的设定变化（人物关系推进/伏笔铺设/道具首次出现）。
3. 更新项目索引：本章改变了什么、留下了什么待解决的问题、本章钩子类型。
4. 记录本章完成状态（已完成初稿/通过自查/待合并）。

### 5 章合并审查稿

每完成 5 章（通过各自自查清单）后：

1. 把 `03-chapters/ch???-???/ch???.md…ch???+4.md` 的正文**按顺序原样拼接**成同目录下的 `ch???-???.md` —— 合并稿只拼接，不重新润色、不统一改字，避免引入新的 continuity 风险。
2. 在合并稿顶部加一段"本批交付说明"：
   - 覆盖章节区间与各章英文标题
   - 每章章末钩子类型清单
   - 本批关键决策变更（如新落地的角色/新制度/新道具）
   - 待作者确认的问题
3. 告知作者本批合并稿已交付，等待整批反馈；反馈回来再决定下一批是否需要回修。
4. 等作者给出整批方向性意见后再推进下一批 5 章；作者未反馈前可继续写下一批的章纲和首章初稿，但不再累积第二批合并稿。

### 串行原则

- 上一章未完成/未通过自查，不开始下一章。
- 上游决策（世界观/角色/POV）发生变更，先回查受影响章节，标注需复核，再继续推进。
- 不用并行翻译多章来绕过连续性——并行会让连续性追踪失效。

### 中断恢复

会话中断后，新会话开始时：
1. 读取项目索引（不依赖聊天记忆），确认 POV、承载角色、本批交付位置。
2. 确认当前已完成章节、在写章节和下一章原文；确认上一批合并稿的作者反馈状态。
3. 确认待解决问题清单。
4. 再开工。

## 7. 审校与交付

**做什么**：对完成章节（或全书）进行系统性审校，交付可阅读的正文。

### 审校五维

逐维过稿，每个实质问题给出：原文/稿件位置 → 问题描述 → 原因→ 修法 → 修后检查。

**① 来源与范围**
- 是否实际读全了需处理的章节？
- 章节对应、人物身份和关键事件是否有原文出处？
- 漏读和推断有没有说明？

**② 因果与文化**
- 新制度是否真能支撑人物行动（有权限、有动机、有代价）？
- 人物有没有被剥夺合理的替代选择？
- 迁移是否破坏了作者保护的体验？

**③ 连续性**
- 人名别名、身份、关系、时间轴、知识边界和伏笔是否全书一致？
- 检查正文，不只检查备注和索引。

**④ 语言与声音**
- 对话是否符合人物在当前关系/场合下的语域？英文对白是否控制在每句 ≤15 词？
- 叙述是否保持 POV？承载角色之外的心理有没有误闯入？修辞是否起作用？
- 整段连读对话——回应接得住吗？潜台词改变了吗？
- 是否把所有角色写成同一口吻？对话标签黑名单有没有出现？

**⑤ 体验与范围**
- 冲突、压力、选择与后果是否连贯？
- 章末钩子是否齐备且类型分布合理（同类型不连续两章）？
- 是否兑现了本轮任务范围？有没有多写未授权内容？

### 交付清单

正文（作者可直接阅读的稿件）+ 简短说明：
- 本轮覆盖范围（起止章节）
- 关键改造决策（世界观/角色层面的主要变化）
- 已修问题（审校中发现并处理的）
- 待核实 / 需作者决定的事项
- 当前版本标记

**不要**：用一堆分析报告替代正文；把术语表维护和一致性追踪交还给作者。

**本地文件**：写成功只算文件已保存，不代表文学质量通过。平台模式另需候选ID和回读确认。

每本书维护一份索引文件（文件名不固定，以项目名区分即可）。内容按需记录，不强制填满所有字段：

```
- 下一步：第 X 章

【世界观决策摘要】

【待解决问题】
- （问题描述 + 影响章节 + 状态）

【变更记录】
- （什么改了，影响哪些章节，旧稿是否需要复核）
```

## 裁减指引

| 任务类型 | 可跳过的阶段 | 必须执行的阶段 |
|---|---|---|
| 单章试译（1-3章） | 4（大纲）可简化，6中的「每章循环」按完整执行 | 0确认 → 1原著分析（本轮范围） → 2+3决策（影响本轮的部分） → 5试写→ 6翻译 → 7交付 |
| 仅审校现有稿件 | 0-6| 7审校（读原文+读现有稿件，不跳过任何一步） |
| 续写（中断恢复） | 0-5（若决策已定） | 6中断恢复流程 → 继续6 → 7 |
