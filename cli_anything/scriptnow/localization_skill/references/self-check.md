# 技能自检协议（版本迁移）

本文件处理 **用户带着已有项目回来**、而 skill 版本已经更新的情况。目标是让 agent 主动发现旧版产物与新版规则的差距，把差距结构化地交给作者决策，不悄悄用新规则覆盖旧内容，也不装作什么都没变。

---

## 一、何时触发自检

自检有**三种触发机制**叠加，覆盖"该触发没触发"和"误触发"两端。

### 机制 A：自动触发（agent 主动，默认开）

**条件**：会话里出现以下任一产物 + 项目索引头部 skill 版本字段低于当前 skill 版本或缺失。

- `[书名]/01-plan/项目索引.md`
- `[书名]/01-plan/角色档案.md` / `[书名]/01-plan/世界观决策.md` / `[书名]/01-plan/大纲.md`
- `ch???.md` / `ch???-???.md`
- 外部稿件（用户带进来问"能不能继续"的任何正文文件）—— 视为"未知版本"

**判断逻辑**（每次会话开始、每次 skill 加载时跑一遍）：

1. 有没有项目索引文件？没有 → 新项目或讨论场景，不自检
2. 有 → 读项目索引头部的 skill 版本字段
3. 字段等于当前版本 → 不自检
4. 字段低于当前版本或缺失 → 走自检；动已完成内容前先问作者

一次会话只自动触发一次。作者在本次会话里选了"暂不决定"或"跳过"，本次会话内不再弹；下次新会话打开该项目仍会提（跳过不代表版本字段升级，故意的）。

### 机制 B：明确触发词（作者主动，随时可用）

作者说下列任一指令，agent 立刻走**完整版**自检，跳过机制 A 的判断逻辑：

**斜杠指令**（精确、不歧义）：
- `/自检`
- `/check`
- `/升级检查`
- `/skill-check`

**自然语触发词**（宽松匹配）：
- "检查一下这本书" / "审一下 [书名] 现在的状态"
- "这本书升级下" / "升级到最新规则"
- "先过一遍再写" / "过一遍硬项"
- "技能升级了检查下" / "新规则看看旧稿怎么样"
- "有没有要回修的"

**外部稿件强制走**：作者说"这本书是别处写的，能不能接着写"→ 不问版本，直接走自检（外部稿必然是"未知版本"）。

### 机制 C：强制触发节点（硬检查点）

某些节点上自检是**必须**跑的，不受机制 A 的"一次会话一次"限制：

| 节点 | 触发强度 | 范围 |
|---|---|---|
| 每卷结束后 | 简化版（只扫内容层硬项） | 本卷已完成章节 |
| 全书终审前 | 完整版 | 全书 |
| 批次合并稿缺失补齐时 | 简化版 | 该批次 5 章 |
| 作者报"稿件质量下降了" | 完整版 | 最近 2 批（10 章） |

这些节点由节奏驱动，不等作者主动说。

### 机制 D：禁用触发词（作者跳过）

作者不想被自检打扰时，用下列指令一次性跳过：

**斜杠指令**：
- `/跳过自检`
- `/skip-check`

**自然语**：
- "不用检查，继续写"
- "先不管这个，继续"
- "知道了，往下写"

跳过的作用范围：

- **本次会话内不再自动弹自检**（机制 A 不触发）
- **但强制节点（机制 C）仍然会触发** —— 卷结束和全书终审是质量底线，不能跳
- **机制 B 仍可用** —— 作者改主意后随时可以 `/自检` 手动叫起
- **项目索引里追加一条跳过记录**，便于下次新会话打开时提醒

```
YYYY-MM-DD：作者选择跳过 v??? → v1.7.0 自检，继续按旧版方法推进；已完成章节与新规差距未评估。
```

### 触发判定伪代码

```
会话开始 / skill 加载时：
  if 作者刚说明确触发词（机制 B）:
      跑完整版自检
  elif 到达强制节点（机制 C）:
      跑对应范围自检
  elif 检测到旧产物 + 版本低（机制 A） and 本次会话未跳过:
      提示 + 跑完整版自检
  else:
      不自检，按正常流程走
```

## 二、自检三层扫描

### Layer 1：项目索引字段完整性（结构层）

对照 [intake.md 项目索引模板](intake.md) 的当前字段清单，标记：

| 字段 | 新版要求 | 旧项目常见缺失 |
|---|---|---|
| skill 版本 | `v1.9.0` 或更高 | 完全缺 |
| 项目文件夹结构 | `workspace/[原书名]/` + 00-source/01-plan/02-outlines/03-chapters/04-review/05-delivery | v1.8.0 前常是根目录平铺 `[书名]-xxx.md` |
| POV 决策 | 承载角色 / 第一人称 / 双 POV 规则 | v1.5.x 前缺 |
| 姓氏策略 | 全西化 / 保留华裔名单 | v1.5.x 前缺 |
| 交付节奏 | 逐章 + 每 5 章合并稿 | v1.5.x 前缺 |
| 当前批次位置 | `ch006-010 写作中` | v1.6.0 前缺 |
| 全书术语表 | `01-plan/术语表.md` 独立文件 | 常见只有人名对照 |
| 人物当前状态表 | `01-plan/角色档案.md` 独立区块（含知识边界） | v1.7.0 前缺 |

缺哪些字段立即列出来，不替作者猜默认值 —— 问他。

**结构迁移特例**：若发现 v1.8.0 前的根目录平铺产物（`[书名]-项目索引.md` / `[书名]-ch001.md`…），差距报告里记为"🟡 结构迁移"，弹窗问作者是否按新结构重排（见 §四 弹窗 4）。不迁移就留原路径，self-audit 的后续扫描改扫根目录。

### Layer 2：已完成章节的新版硬项（内容层）

抽样已完成章节（首章 + 最新一章 + 随机中段一章，共 3 章），过硬项清单：

**对白五维量化**（v1.9.0 新增，跑 [dialogue.md §三](dialogue.md) 的量化自检；agent 现场写一次性脚本即可）：
- 对白字符占比 > 60% → 记一条"叙述被挤压"
- 最长连续纯对白 > 2 行 → 记一条"缺包裹层"
- 对白后紧跟描写比例 < 60% → 记一条"水对白"
- 对话标签多样性 < 5 种 / said 占比 > 80% → 记一条"标签单调"

**章末钩子类型自检**（v1.9.0 新增，对照 [chapter-hooks.md §二](chapter-hooks.md) 八种类型）：
- 章末最后 3 行能否明确归入八种之一？不能 → 记"无钩子"
- 是否出现 §一 三条反例（总结式 / 预告式 / 情绪抒发式）？出现 → 记"伪钩子"
- 本批次 5 章内同类型钩子是否 > 2 次？是 → 记"钩子分布失衡"

**拼音残留扫描**（grep 当前项目 `03-chapters/` 下所有 `ch*.md`；旧项目若还在根目录平铺，先问作者要不要迁到新结构，不迁就扫根目录）：
- 拼音姓氏：`Chen`/`Liu`/`Wang`/`Zhang`/`Zhao`/`Li`/`Wu`/`Zhou`（+名）
- 混合名：`Mrs. Chen`/`Tessa Liu` 模式（英文名+拼音姓）
- 中文地名音译：`Ning City`/`Beijing City` 等未授权保留
- 中式称呼：`Young Master`/`Young Miss`/`Director Lu`/`Lawyer He`/`Big Boss`

**公制/货币残留**：
- `km`/`kg`/`cm`/`℃`/`公里`/`公斤`/`米`/`摄氏度`/`元`/`人民币`/`RMB`

**对话标签黑名单**：
- `smiled and said`/`looked at her and said`/`said with a cold expression`/`laughed coldly`/`said with a cold snort`

**POV 一致性采样**：
- 读首章开头 500 词，判断用的是第一人称还是第三人称；记录承载角色
- 读最新章开头 500 词，对比是否一致
- 如果任意一章出现 `he saw X ... and then she felt Y` 模式（跨人物内心），记为"跳视角"

**章末钩子存在**：
- 读抽样章的最后一段，判断是不是钩子句（见 english-output.md §八）；标记"总结式/预告式/情绪抒发式"收尾
- 两章末尾放一起看，判断钩子类型是否重复

**合并稿存在**：
- 检查目录里有没有 `ch001-005.md` / `ch006-010.md` 格式文件；如果已完成章节 ≥5 但没有合并稿，记一条

### Layer 3：方法层差距

这一层不扫描文件，只对照项目索引的方法说明和实际稿件做判断：

- 有没有做过首批 5 章 gate 验收？（v1.7.0 后硬项）
- 有没有每章 10 项自查痕迹？
- 有没有本批交付说明里的"下批需承接"段？
- 有没有做过卷级审核？（多卷项目）
- 有没有正文生成和质量审核两遍分离？（v1.7.0 后硬项）

## 三、差距报告格式

扫完三层后，产出 `[书名]/04-review/自检报告-YYYYMMDD.md`，结构：

```markdown
# [书名] 自检报告

**自检时间**：YYYY-MM-DD HH:MM
**原 skill 版本**：vX.X.X（或"未知"）
**当前 skill 版本**：v1.7.0
**项目当前状态**：已完成 ch001-015，正在写 ch016

## 一、结构差距（项目索引字段）
- ❌ 缺 skill 版本字段
- ❌ 缺 POV 决策区块（当前承载角色需确认）
- ❌ 缺人物当前状态表
- ✓ 全书术语表存在但不完整（见下）

## 二、内容差距（已完成章节硬项）

### 拼音残留
- ch003 第 2 段：`Mrs. Chen` （作者是否授权保留？若否需改）
- ch007 第 8 段：`Director Lu` （建议改 `Mr. Lu` 或整名）

### 公制残留
- ch002 开头：`十公里外的山庄` → `ten miles away`
- ch011 中段：`200 元` → 需换成 USD

### 对话标签黑名单
- ch005 第 6 段：`she said with a cold expression` → 改动作标签
- ch012 第 3 段：`he laughed coldly` → 改动作标签

### POV 一致性
- ch001-014：第一人称 I-POV，承载角色 Sophia
- ch008 第 10 段：疑似跳到 Ethan 内心（`He knew she was lying`）→ 需改为 Sophia 的观察

### 章末钩子
- ch001 末：✓ 行动悬停钩子
- ch008 末：❌ 总结式收尾（`That was the longest day of her life.`）
- ch015 末：❌ 情绪抒发收尾

### 合并稿
- ❌ 已完成 15 章但只见 `ch001-005.md`；`ch006-010.md` / `ch011-015.md` 缺

## 三、方法层差距
- 未做首批 5 章 gate 验收（当时版本无此节点）
- 术语表未按新版"即时登记"要求维护，ch008 新道具"玛瑙手串"未入表

## 四、按优先级分档

### 🔴 硬项（影响可读性，建议回修）
1. 拼音残留 3 处
2. 公制残留 2 处
3. 对话标签黑名单 2 处
4. ch008 跳视角 1 处

### 🟡 可选（影响节奏/钩子质量）
1. ch008 / ch015 章末钩子重写
2. 补 ch006-010 / ch011-015 合并稿与本批交付说明

### 🟢 向前应用即可（不回修已完成稿）
1. 项目索引字段补齐
2. 人物当前状态表从 ch016 开始建
3. 术语表维护流程从 ch016 起按新版即时登记
```

## 四、交给用户决策（弹窗）

差距报告落盘后，**立即用 `ask_user_question` 发弹窗**，不自作主张开修。推荐分 2-3 个关键决策，不要塞成一个长单。

### 弹窗 1：硬项回修范围（必问）

```
header: 旧稿硬项回修
question: 已发现 N 处硬项差距（见自检报告 §二）。要不要回修已完成章节？
options:
- 全量回修（Recommended）：按新版硬项清单把 ch001-015 全部过一遍，回修后再推进 ch016；工期+N 小时，可读性最佳
- 仅硬项回修：只改拼音/公制/对话标签/跳视角，钩子和合并稿保持现状；中等工期
- 向前应用：ch001-015 保持原样，从 ch016 起按新版；工期最快，但已完成稿和新稿风格会有断层
- 暂不决定：继续手写 ch016，自检报告留存，批次末再评估
```

### 弹窗 2：POV 承载角色确认（有歧义时才问）

```
header: POV 承载角色确认
question: 已完成稿看起来是 Sophia 的第一人称。要确认她是全书 POV 承载角色吗？
options:
- 是，Sophia 全书 I-POV：锁定到项目索引，ch016 起继续
- 切换为双 POV：告诉我副承载角色和切章规则
- 其他：告诉我新的承载角色（前面可能需要回修）
```

### 弹窗 3：合并稿补齐（可选）

```
header: 旧批次合并稿
question: 已完成 ch001-015 但缺 ch006-010 / ch011-015 合并稿。要补吗？
options:
- 补（Recommended）：把 ch006-010 / ch011-015 拼成合并稿，写"本批交付说明（追认）"；便于后续卷级审核
- 不补：继续前进，接受历史债务
```

### 弹窗 4：项目文件夹结构迁移（v1.8.0 前的项目才问）

```
header: 项目文件夹结构迁移
question: 这本书是旧版结构（所有文件平铺在工作区根目录）。要迁到新结构 `[原书名]/{00-source,01-plan,02-outlines,03-chapters,04-review,05-delivery}/` 吗？
options:
- 迁（Recommended）：agent 自动建新目录 + 把现有文件移到对应子目录 + 更新项目索引里的路径字段；回修工期 10-20 分钟
- 不迁：保持根目录平铺；项目索引标注"旧结构"；后续新文件仍按新规则命名（会出现混合状态）
- 只迁规划文件：角色档案 / 世界观 / 大纲移到 01-plan，正文章节保持原位；最轻的迁移
```

### 弹窗 5：v1.8.0 → v1.9.0 对白与钩子回修（旧项目升级到 v1.9.0 时才问）

```
header: 对白五维 + 章末钩子回修
question: v1.9.0 新增了对白五维量化（水对白判定）与章末钩子八类（含反例黑名单）。扫出 M 处对白塌方 + K 处伪钩子（见自检报告 §二）。要不要对历史章节回修？
options:
- 批次性回修（Recommended）：对距离当前最近的 1-2 批（5-10 章）走 Pass 2 五维扫一遍 + 钩子类型重写；工期 +1-2 小时，可读性恢复最佳
- 仅重写章末钩子：只处理伪钩子章节，对白五维在新章执行即可；中等工期
- 向前应用：ch001-N 保持原样，从下一章起严格按五维 + 八类；工期最快，风格会断层
- 暂不决定：报告留存，下批次末再评估（agent 在下一次 Pass 2 自动复查提醒）
```

**弹窗 5 触发条件**：
- 项目索引 skill 版本字段 < v1.9.0 且扫出至少 3 处对白五维红线 **或** 至少 2 处章末伪钩子
- 不满足触发条件时不弹，仅在报告里标"向前应用"即可

### 弹窗设计要点

- **每个选项第一句就说取舍**（工期/可读性/风格统一）
- **推荐项标 Recommended 并置顶**；推荐依据是"让下一批 agent 工作面最干净"
- **允许"暂不决定"**（这是用户的私有区权力）
- **一次最多 3 个弹窗同屏**；弹窗 4（结构迁移）/弹窗 5（v1.9.0 对白钩子）只在真正触发条件时追加；更多的放进差距报告里等下次自检或等用户主动翻

## 五、决策落地

用户选完后：

1. **在自检报告底部追加"用户决策"段**，一条一条写：
   ```
   弹窗 1：仅硬项回修
   弹窗 2：是，Sophia 全书 I-POV
   弹窗 3：补
   决策时间：YYYY-MM-DD HH:MM
   ```

2. **按决策推进**：
   - 回修类：按差距报告的位置清单逐一改；每改一处记在报告"回修日志"段
   - 向前应用类：更新项目索引字段，在变更记录里写明"自 ch??? 起适用新版规则"
   - 暂不决定类：自检报告留存；在项目索引"待决定"段记一条

3. **更新项目索引的 skill 版本字段**：
   ```
   skill 版本：v1.9.0（自检迁移自 v1.X.X，于 YYYY-MM-DD 完成）
   ```

4. **对后续章节生效**：从下一章起，10 项自查、三层生产资料、人物当前状态表、**对白五维量化 + 章末钩子八类**全部按新版走。

## 六、自检本身不是量产

自检一次只做一次、产一份报告。作者选完就走到正事上：

- **不把自检变成每批次的例行检查**；每批次的质量在 [review.md](review.md) 的 Pass 2 里管
- **不把自检用作查错工具**；查错是 Pass 1 单章 10 项自查的事
- **自检只处理"版本迁移"这个瞬间**；平时按正常流程走

迁移完成后，skill 版本字段升到当前版本，下次不再触发自检，直到下一次升级。

## 七、跨项目升档扫描（自检完整版附带）

每次**完整版自检**（机制 B / 机制 C 的完整版触发）在落完本项目决策后多走一步 —— 扫所有项目的手法库，找出**出现 ≥ 3 次**的条目，提升档弹窗。

### 扫描步骤

1. `glob` `workspace/*/04-review/手法库-补录.md`
2. 对每个文件按"归属维度 + 条目简称"分类
3. 跨项目同名 / 同类条目计数
4. 命中 ≥ 3 次的条目，按 [feedback-library-template.md §升档流程](feedback-library-template.md) 生成弹窗

### 升档审慎性

- **每次自检最多提 1 条升档建议**（作者精力有限）
- **升档必须作者点头**，agent 不自动改 reference 文件
- 升档承诺写进下一个 skill 版本的 changelog
- 冲突条目（放宽现有阈值）必须明示风险

**本机制在作者长期用这个 skill 做多个项目后才显露价值**；初期 1-2 个项目时跳过本步骤即可。
