# 接诊与文档化协议

收到翻译或重构需求时，**不立刻读原文、不立刻动手**。先走接诊对话，建立项目索引，再按阶段推进。文档是记忆体，不是副产品——每个阶段的产出必须落文件，新会话优先读文件而不是依赖聊天记忆。

---

## 一、接诊对话（开工前）

### 第一轮：判断路径（1个问题）

收到需求后，先问：

> 「您想做哪种处理？
> - **归化翻译**：保留原故事骨架，调整语言和文化载体，出英文版（读者能认出是哪部中文小说的英文版）
> - **跨文化重构**：以原作为素材，改编成全新品类（狼人/黑帮/吸血鬼等），产出一部全新英文作品（读者认不出原作）
> - **还没想好**：先聊聊原作和目标市场，再决定」

等作者明确回答后，进入第二轮。

---

### 第二轮：按路径深问（6-8个问题，分两组）

**通用问题（两条路径都问）**：

1. **目标市场**：英语哪个市场？（美区Goodnovel / Webnovel / Amazon KU / 英区 / 其他）单章字数有要求吗？
2. **处理范围**：全书翻译，还是先处理指定章节？
3. **交付节奏**：分批交付（每个阶段完成就给），还是全部完成再交？
4. **保护项**：原作里哪些内容/关系/情感体验是必须保留的？（请用原话描述，我按字面理解，不自行解释）

**路径一·归化翻译追加**：

5. **本地化深度**：全西化（命名/制度全部西化），还是保留中国背景用英文连载？
6. **已有资源**：有没有已确定的英文人名、术语表、或参考的竞品？

**路径二·跨文化重构追加**：

5. **目标品类**：具体品类是什么？有没有参考书目（希望像哪本书的风格）？
6. **品类核心卖点**：这个品类读者最期待什么场景？（例：狼人文读者期待 mate bond 触发、mating mark）
7. **改编自由度**：原作情节可以大幅改动，还是核心情节线要保留？

---

### 第三轮：确认并建档（收到回答后）

把第二轮的回答复述一遍，请作者确认：

> 「我来确认一下我们的计划：
> - 路径：[归化翻译 / 跨文化重构]
> - 目标：[平台+ 市场]
> - 范围：[全书 / 指定章节]
> - 本地化深度：[全西化 / 保留背景]
> - 保护项：[原话]
> - 第一步：[开始阶段0/步骤①]
>
> 确认无误我就建立项目文件，开始第一步。」

作者确认后，**立即建立项目索引文件**（见下节），再进入工作流。

---

## 二、项目索引文件

### 文件命名与位置

```
[书名]-项目索引.md        # 主索引，每次新会话首先读这个
[书名]-原著分析.md         # 阶段1/步骤②产出
[书名]-世界观决策.md       # 阶段2/步骤④产出
[书名]-角色档案.md         # 阶段3/步骤⑤产出
[书名]-大纲.md             # 阶段4⑦产出
[书名]-章纲.md             # 步骤⑧产出（重构路径）
[书名]-ch001.md            # 逐章正文
[书名]-ch002.md
...
```

文件名用书名前缀统一管理。位置沿用作者目录，不强制创建数据库结构。

## 三、逐阶段文档交付清单

每个阶段完成后，输出对应文件，更新索引，等作者确认关键节点后再推进。

### 路径一·归化翻译

| 阶段 | 产出文件 | 内容摘要 | 是否等确认 |
|------|----------|----------|-----------|
| 0启动确认 | `项目索引.md`（建立） | 接诊信息全部写入 | ✓ 等确认 |
| 1 通读分析 | `原著分析.md` | 叙事骨架、文化机关清单、待核实项| 否（继续推进） |
| 2 世界观 | `世界观决策.md` | 制度/地名/货币/机关重建决策 | ✓ 等确认（有保护项冲突时必须等） |
| 3 角色 | `角色档案.md` | 人名对照表、称谓规则、声线关键词 | ✓ 等确认 |
| 4 大纲 | `章节标题对照表.md` | 原标题→英文标题、工作批次 | 否 |
| 5 试译 | `试译样段.md` | 样段正文+验证说明 | ✓ **必须等作者确认** |
| 6 逐章 | `ch001.md` / `ch002.md`… | 正文 | 否（串行推进） |
| 7 审校 | 修订回正文 + `交付说明.md` | 审校报告+修订后正文 | ✓ 等确认 |

### 路径二·跨文化重构

| 步骤 | 产出文件 | 内容摘要 | 是否等确认 |
|------|----------|----------|-----------|
| ① 素材输入 | `项目索引.md`（建立） | 接诊信息 | ✓ 等确认 |
| ② 原著分析 | `原著分析.md` | 六维分析、保护项 | 否 |
| ③ 品类确定 | 追加到索引 | 品类、卖点、平台 | ✓ **必须等确认** |
| ④ 世界观 | `世界观决策.md` | 权力架构、能力体系、地理机构 | ✓ 等确认 |
| ⑤ 人物| `角色档案.md` | 人名、身份、关系图、声线 | ✓ 等确认 |
| ⑥剧情映射 | `剧情映射.md` | 原情节→新情节对照 | 否 |
| ⑦ 大纲 | `大纲.md` | Logline、三幕、分卷、感情线 | ✓ **必须等确认** |
| ⑧ 章纲 | `章纲.md` |逐章事件/冲突/钩子 | 否（按卷分批） |
| ⑨ 逐章 | `ch001.md`… | 正文 | 否（串行推进） |
| ⑩ 审校 | 修订回正文 + `交付说明.md` | 六维审校 | ✓ 等确认 |

## 四、新会话恢复协议

会话中断或跨天继续时，**新会话第一步固定是**：

```
1. 请作者提供项目索引文件路径
   （或在工作区直接找[书名]-项目索引.md）

2. 读取项目索引，确认：
   - 当前处于哪个阶段
   - 已完成哪些文件
   - 待解决问题清单
   - 下一步是什么

3. 读取下一步所需的相关文件
   （例：准备写ch003，就读角色档案 + ch002结尾 + ch003章纲）

4. 向作者报告：
   「我已读取项目文件，当前进度是 [X]，
    上次完成了 [Y]，
    本次继续 [Z]，请确认。」

5. 作者确认后开工。
```

**禁止**：依赖聊天记忆声称记得设定；问作者「上次说的那个人叫什么来着」；在没有文件依据的情况下声称某个决策已经确定。

---

## 五、文档更新规则

- **每章完成后**：更新索引里的「当前进度」和「已交付文件清单」
- **有新决策时**：追加到对应决策文件（世界观/角色档案），同时在索引「变更记录」里登记
- **发现前后不一致时**：在「待解决问题」里登记，标明影响章节，不悄悄修改已交付正文
- **作者修改保护项时**：更新索引「作者保护项」，在变更记录里说明旧设定和新设定的差异，回查受影响章节

---

## 六、文档即记忆体——核心原则

>凡是对后续创作有影响的决策，都必须落文件。
> 凡是没落文件的，视为未决策，不能在正文中悄悄实施。

- 对话里的讨论 ≠ 已确认决策
- 文档里的草稿 ≠ 作者已采纳
- 文件写成功≠ 文学质量通过
- 只有作者明确确认的，才算决策生效
