# 手法库-补录模板

> **本文件是模板，不是实际手法库**。每个项目都会在 `workspace/[原书名]/04-review/手法库-补录.md` 生成自己的副本，由 agent 在 Pass 2 / 卷审 / 全书终审时增量追写。
>
> 跨项目沉淀机制：self-check 协议每次触发时顺带扫一遍各项目的手法库-补录，若**同一类型手法在 3 个独立项目都出现**，触发升级弹窗问作者是否把该手法升档进对应 reference（dialogue.md / chapter-hooks.md / pacing-benchmarks.md …）。
>
> 当前 skill 版本：`v1.9.0`。本文件首次引入。

---

## 为什么要有这个文件

**问题**：Pass 2 审读经常发现新的塌方模式或修法，但没地方记 —— 下次换项目就忘了。

**解法**：每次 Pass 2 发现一条"值得记"的东西（新塌方 / 新修法 / 新钩子类型 / 新品类节奏特征），**即时**追到本项目的 `手法库-补录.md` 里。

**判定"值得记"的标准**：
- 本 skill reference 现有的五维 / 八类 / 九字段之外的东西
- 或现有条目的**更强形态**（更好的反例 / 更精确的阈值 / 更简洁的修法）
- 或**与现有条目冲突**的证据（比如某品类的 said 占比就是正常值 > 80%）

## 追写格式

每条记录按下面的结构追到项目手法库文件末尾：

```markdown
---

### [YYYY-MM-DD] [条目简称]

**来源章节**：ch??? / 批次 ch???-???
**归属维度**：对白 / 章末钩子 / 节奏 / 连续性 / 其他（简述）

**现象**：
一句话说清楚看到了什么。

**样本证据**（原文摘录 / 匿名化后）：
```
[摘 2-5 行实际稿件，保留必要上下文；不超过 10 行]
```

**现有 reference 覆盖情况**：
- 已覆盖：XXX reference §Y 条
- 未覆盖 / 边缘：描述缺口
- 冲突：描述与哪一条冲突

**建议处理**：
- 本项目内：是否回修？（是/否 + 理由）
- 跨项目升档：是否建议升档到 reference？（是/否 + 理由）

**作者裁决**（agent 不自行决定）：
[等作者过目后填]
```

## 升档流程（agent 自动走）

每次 **self-check 协议完整版** 触发时，agent 多做一步：

1. `glob` 当前 `workspace/*/04-review/手法库-补录.md` 列出所有项目的手法库
2. 按"归属维度 + 条目简称"归类统计，找出**出现 ≥ 3 次**的条目
3. 对每个符合条件的条目，生成 `ask_user_question` 弹窗：

```
header: 手法库升档建议
question: 以下手法在 N 个项目反复出现，建议升档到正式 reference —— 是否同意？

现象：[XXX]
已在 [项目 A / 项目 B / 项目 C] 出现
建议升档到：[dialogue.md / chapter-hooks.md / pacing-benchmarks.md] §新增条目

options:
- 升档（Recommended）：agent 把该条形式化、加入对应 reference 下个版本，并在 changelog 记录；升档后下一个 skill 版本触发自检提醒
- 保持现状：只留在手法库，不进 reference；下次触发不再提示该条
- 需要我看一下再定：agent 把三份项目的原始条目整理成简报让作者看
```

**升档的审慎性**：
- **每次自检最多提 1 条升档建议** —— 作者精力有限
- **升档必须作者点头**，agent 不自动改 reference 文件
- **冲突条目**（如 "said 占比 > 80% 在 billionaire 品类正常"）提升档建议时附上"这将放宽现有阈值"的明确说明，避免悄悄弱化质量底线

## 反面：什么**不**写到手法库

避免把以下内容塞进来污染数据：

- ❌ **本章特有的情节判断**（"ch005 结尾那句写得好棒" —— 这是编辑意见，不是手法）
- ❌ **作者偏好**（"作者喜欢长段落" —— 这是项目设置，写进项目索引）
- ❌ **一次性偶发错误**（手残打错字 —— Pass 1 的事，不是手法）
- ❌ **工具 bug / 平台问题**（这些给 feedback skill 或系统日志）

手法库只装**可复用的叙事/对白/节奏规律**。

---

## 与 reference 的边界

| 类型 | 放哪里 |
|---|---|
| 单项目一次性发现 | `04-review/手法库-补录.md`（即项目副本） |
| 2 个项目出现同一现象 | 继续留在各自手法库，Pass 2 时做交叉引用笔记 |
| 3+ 项目出现同一现象 | self-check 弹窗建议升档到正式 reference |
| 作者明确说"这条应该写进 skill" | 立即升档，不等 3 次 |

## 本文件自身的维护

本模板由 `webnovel-localization` skill 官方维护。**每次 skill 版本更新**，agent 应比对本模板与各项目手法库的字段差异 —— 字段丢失的项目手法库在 self-check 时提示补齐。

**agent 发现本模板本身需要改进时**（例如"归属维度"字段不够用），记一条到 agent 自己的工作笔记，等作者下次主动讨论 skill 迭代时提出，不自作主张改模板。
